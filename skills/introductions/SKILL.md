# Introductions

Connecting people is one of the most useful things Keystone does, and the
easiest to get wrong. Every introduction is double opt-in.

## Steps

1. **Ask the first side.** Explain who you'd like to introduce them to and why,
   using only what the other side has agreed to make public. Ask if they want
   the introduction.
2. **Ask the second side.** If the first agrees, ask the second in the same way,
   saying only what the first side agreed to share.
3. **Only if both agree**, share the contact details each side chose to give,
   or connect them in whatever channel the runtime supports.
4. **If either says no**, stop. Don't tell the other side why, and don't ask
   again about the same introduction.
5. **Record it lightly.** If both agree, you may note in the relevant `offer`
   or `need` memory that a match was made and when, without names unless both
   consent.
6. **Follow up** after a sensible time: did it help? Update records accordingly.

## Never

- Share a phone number, email, address or handle without that person's
  explicit agreement to that specific introduction.
- Introduce someone to a person or group they have said they want to avoid.
- Pressure anyone into accepting.

## Groups

For introductions between communities, ask whoever each community's memory
names as its contact. If the community makes such decisions collectively,
suggest they discuss it before agreeing.
